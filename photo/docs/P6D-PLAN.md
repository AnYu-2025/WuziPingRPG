### 2.3 序 1 · g1 内存门（本轮核心）

#### 2.3.1 风险陈述（先把账算清）

| 事实 | 数字 | 来源 |
|---|---|---|
| 24MP（6000×4000）导出峰值 | **1.28 GB / 21 s** | `bench.mjs` 实测 |
| 单张 RGBA 缓冲 | 24MP → 96 MB；50MP → **204 MB** | w × h × 4 |
| `oversize` 阈值 | `MAX_HEAVY_PIXELS = 30_000_000`（30MP） | `pixels/effects.ts` |
| 50MP 导出外推 | ≈ 1278 MB × (51.1 / 24) ≈ **2.7 GB** | 按像素比线性外推 |
| `estimateMemory` 性质 | **像素管线下界**（实测 ≈ 估算 × 2） | `bench.mjs` 结论 |

> **结论**：24MP 只是"勉强吃下"；50MP 中画幅（商业级真的会遇到）会越过 3 GB 安全线。
> 现在 `oversize` 只是**一句告警**，背后**没有任何策略**。P6-d 必须正面回答：
> **拒绝 / 降质 / 分块，到底选哪个、在什么条件下选。**

#### 2.3.2 策略

**唯一原则：绝不静默。**
超预算时，要么降采样并**明确告知**，要么让用户**知情确认**，要么**明确拒绝**并说明原因 ——
绝不"悄悄 OOM"，也绝不"悄悄降质"。（与内核 `sanitize` 的"绝不静默碎图"同一条铁律。）

| 层级 | 触发条件 | 动作 | 依据 |
|---|---|---|---|
| 预览 | 任意源图 | **恒走 `PREVIEW_TARGET`（长边 1400）** | 预览与源图大小**解耦** → 超大图预览完全不受影响（已实现，继续沿用） |
| 导出 | 预测峰值 ≤ 预算 | **直接执行** | — |
| 导出 | 预测 > 预算，且降采样可行 | **默认降采样**到最大可行长边，并**告知**实际导出尺寸 | 商业级多数用途不需要原尺寸；与"绝不静默"一致 |
| 导出 | 预测 > 预算，用户**显式要求原尺寸** | **二次确认**后执行（用户知情并承担风险） | 尊重用户选择，但风险必须知情 |
| 导出 | 连单张缓冲都超硬上限 | **拒绝**并说明原因 | 不让它崩 |

> **为什么不是"分块"**：分块（条带流式编码）才是真正的商业级答案，但它要求编码器支持
> **流式 / 逐块写出**（PNG 可逐行；JPEG 需 MCU 对齐）。成本高 —— 列为 **序 8（m1）** 的
> **调研项**：先有策略，再有实现。

**预算与判定量**

- 预算默认 **2 GB**（可用环境变量 `PHOTO_MEMORY_BUDGET_MB` 覆盖）。
- 判定量 `projected = estimateMemory(plan, { cacheSnapshots: 0 }).peakBytes × SAFETY`，
  其中 **`SAFETY = 2.0`** —— 直接来自 `bench.mjs` 的结论"实测 ≈ 估算 × 2"。
- 导出走 `EXPORT_TARGET`（`maxEdge: 0`，**不带缓存快照**），故 `cacheSnapshots: 0`。

#### 2.3.3 验收

| # | 条件 | 怎么验 | 严重度 |
|---|---|---|---|
| **J** | 准入判定是**纯函数** | 内核 `pipeline/memory.ts#gateExport(input): ExportGate`，返回 `run \| downscale \| confirm \| reject`；**四分支各有单元用例** | ✅ 已完成 |
| **K** | 50MP 真图不崩 | 导入 ~50MP 图：**执行前拦截**，零 OOM、零进程被杀 | ✅ 已完成 |
| **L** | 策略可见 | 导出前展示 `describeMemory` 的峰值估计；超预算时文案写明动作与目标尺寸 | ✅ 已完成（CLI 已接） |
| **M** | 分块可行性结论 | PNG / JPEG 分块流式编码的**可行性 + 代价**结论，只出结论不实现 | P2（序 8） |

> **J 为什么放内核、不放壳**：准入是**策略**，不是交互。放内核 → CLI 批处理、web、移动端
> 可复用**同一条规则**；壳只负责把 `ExportGate` 翻译成对话框。这也守住了"壳不许有逻辑"。
> 参照 `estimateMemory` 已有的先例（内核出预算、外壳出交互）。

#### 2.3.4 落地（序 1 实施记录）

- **内核**（`packages/core/src/pipeline/memory.ts`）：
  `gateExport` 四分支 + 常量 `EXPORT_MEMORY_SAFETY = 2.0`、`DEFAULT_EXPORT_MEMORY_BUDGET_BYTES = 2 GiB`、
  `DEFAULT_EXPORT_MEMORY_HARD_LIMIT_BYTES = 4 GiB`、`MIN_DOWNSCALE_LONG_EDGE = 640`。
  判定顺序：`projected ≤ 预算` → run；否则（未锁原尺寸）二分求**预算内的最大长边** → downscale；
  降不下来或锁了原尺寸 → 超硬上限则 reject，否则 confirm。
  `planFor` 缺省时**刻意不给**降采样方案（没有"按 maxEdge 重建计划"的能力，就不擅自降质）。
- **预算注入**：内核不读 `process.env`；CLI 读 `PHOTO_MEMORY_BUDGET_MB`（非法值写 stderr 警告后回落默认，**不静默**）。
- **CLI 接线**（门的**第一个消费者**，证明"策略放内核"可复用）：`plan` / `render --dry-run` 报告里输出
  `内存门[decision]：文案`；`render` 按门的建议用**同一个 `buildPlan`** 换 `maxEdge` 重建并执行；
  `confirm` 分支需 `--allow-oversize` 放行（非交互场景="知情确认"的等价物）。
- **实测复核**（24MP 真图 6000×4000 + 锐化/去雾）：

  | 场景 | 结果 |
  |---|---|
  | 默认 2 GB 预算 | `run` —— 预计峰值 **1281.7 MB**（与 bench 实测 1.28 GB 吻合） |
  | 预算 100 MB | `downscale` —— 长边 6000 → **1676**（输出 1676×1117，预计峰值 100 MB） |
  | 预算 20 MB（真渲染） | 落盘 749×499 / 1.43 MB；**逐字节 == `--long-edge 749` 直渲产物**（守住 §4 同源断言） |
  | 50MP 计划（8688×5784）| `downscale` → 长边 7589；**maxRSS 全程 45 MB**（未分配任何像素缓冲）|

## 4. 回归要求（每项必留）

- 新接的**每一项能力**：至少一条用例，**优先**补「预览 == 导出同源」断言。
- 功能对齐项：**每项附一条 smoke 断言**（P0 硬要求，不是可选项）。
- 内存策略：
  - `gateExport` **四分支全覆盖**（run / downscale / confirm / reject）；
  - 加一条"**降采样导出的产物，逐字节等于同 `maxEdge` 直渲的产物**"。
    理由：降采样必须复用**同一个** `buildPlan`，只是 `maxEdge` 不同 ——
    否则"预览/导出同源"这条架构保证就被悄悄打破了。
- 打包：**打包后的产物**必须能跑通 smoke（不只是开发机）。
- 纯视图项（缩放、对比原图、直方图展示）可豁免，但须在 `DESKTOP-PARITY.md` 备注列注明。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| "内存策略"被偷换成"弹个告警" | J 是**纯函数 + 四分支用例**，不接受"弹了个提示"就算做完 |
| 降采样破坏"预览 == 导出同源" | §4 专项断言（降采样产物 == 同 maxEdge 直渲产物） |
| 50MP 真 OOM | K 用真实 ~50MP 图验收；`gateExport` 必须在**执行前**拦截 |
| **打包后白屏**（开发机正常 / 装完打不开） | P2 在**全新机器**验收；`app://` 挂载路径随产物结构逐条核对 |
| 打包卡在签名 / 改 exe | `signAndEditExecutable: false` + 注释写明原因（无证书、受限环境必挂） |
| ESLint 引入大量格式返工 | 第 0 步做，**趁改动面还小**；先统一再接新代码 |
| 补壳时把壳写厚（开始算像素） | 仍受 P6-c §3.4 三条禁止约束；发现"壳里必须算像素"就停手补内核 |
| 多端铺开分散精力、壳对齐半途而废 | 先清序 0–3（确定性收益），再谈曲线 / 口语 / 多端 |
| 对齐表与实际脱节，表变成噪声 | 改表必须**同步改统计**；状态**只在代码真的跑通后**才改 |
